# 파일 저장과 인계

## 요약 (먼저 읽기)

아래 열 줄로 대부분의 작업을 처리할 수 있다. 예외 상황이나 세부 규칙이 필요할 때만 그 아래 절을 읽는다.

1. 원본·이전 결과는 보존한다. 쓰기 전에 현재 내용을 확인하고, 수정본은 새 파일(작업번호 +1)로 만든다.
2. 확보한 원본은 `source/`, 분석할 자료는 `data/`에 작업별 폴더로 저장하고 읽을 수 있는지 확인한 뒤 분석한다. 중복 복사·덮어쓰기는 하지 않는다. 사용자가 대화에 붙여 넣은 짧은 자료로 대화 안에서 답하고 끝나는 일은 저장하지 않고 바로 진행해도 된다. 결과를 파일로 남기거나 나중에 이어갈 일, 파일·링크로 받은 자료는 저장한 뒤 분석한다.
3. 원문·사용자 제공 자료·AI가 만든 정리본을 구분하고 출처·날짜·읽은 범위를 남긴다. URL만 적은 것은 본문을 읽은 것이 아니다.
4. 수강생 실습 결과는 `outputs/<작업>/{YYYYMMDD_HHMM}_{작업명}_{모델명}_{작업번호}.{확장자}`. 확인 못 한 값은 `모델미확인`·`시각미확인`으로 쓰고 추측하지 않는다.
5. 에이전트 작업 기록은 `agents_logs/YYYY-MM-DD-모델이름/progress-log.md` 하나에 `## HH:MM — 작업명`으로 누적한다. 모델명을 지어내지 않는다.
6. 새 대화·요청은 `agents_logs/INDEX.md`를 먼저 읽고 이어가기·갱신·새 작업·확인 중 판단한다. 로그 전체는 읽지 않고 관련 구간만 읽는다.
7. 이어가기는 `다음 행동`부터, 갱신은 새 파일로, 새 작업은 색인에 한 줄 추가, 애매하면 사용자가 고른다.
8. 색인·로그에는 개인정보와 자료 본문을 적지 않고 경로와 요약만 적는다.
9. 로그 20KB·색인 완료 항목 10줄을 넘으면 `_보관.md`로 옮기고 요약을 남긴다. 삭제하지 않는다.
10. 파일 작업 후 보고는 `상태 | 작업 기록` / `산출물 | 검증` 두 줄로 한다. 단순 질문·대화에는 붙이지 않는다.

## 저장

- `templates/`, `.skills/`, `data/`의 원본과 이전 결과를 보존한다. 파일을 쓰기 전 현재 내용을 확인한다.
- 분석에 사용할 자료는 먼저 `data/` 아래 작업별 폴더에 저장하고 저장 위치와 읽기 가능 여부를 확인한다. 이미 `data/`에 있는 자료는 중복 복사하지 않는다. 기존 원문은 덮어쓰지 않는다.
- 사용자가 대화에 붙여 넣은 짧은 자료로 대화 안에서 답하고 끝나는 일은 저장하지 않고 바로 진행해도 된다. 결과를 파일로 남기거나 나중에 이어갈 일, 파일·링크로 받은 자료는 저장한 뒤 분석한다. 이 경우 작업 기록과 두 줄 보고도 붙이지 않는다. 사용자가 저장을 원하면 그때 저장한다.
- 이메일(.eml)·문서 등 확보한 원본은 `source/`의 작업별 폴더에 누적 보관한다. 기존 원본을 덮어쓰지 않고 출처·날짜를 식별할 수 있게 한다. 실제 원본을 확보하지 못했다면 원본인 척 만들지 않는다.
- Markdown 기록은 유지하는 것이 원칙이다. 사용자가 `source/`의 PDF·PPT·엑셀 등 원본 파일 삭제를 구체적으로 요청한 경우에는 이미 주어진 지시와 권한 범위에서 해당 파일을 삭제할 수 있다. 대상이 불명확하면 임의로 선택하지 않는다. 원본이 없으면 사람이 원문과 다시 대조하기 어려우므로 그 사실을 알리고, 남은 Markdown 추출·요약본을 원본으로 바꿔 말하지 않는다. 관련 기록과 이전 결과는 보존하며 원본이 삭제된 상태와 확인하지 못할 부분을 남긴다.
- 업무 소통처럼 누적하는 작업용 기록은 기존 내용을 지우지 않고 새 항목이나 변경 이력을 추가할 수 있다. 원본 파일은 별도로 보존하고, 정리 기록과 원문을 구분한다.
- URL·업로드 자료는 확보한 원본을 `source/`에 보존하고 출처·주소·확인 날짜와 접근 범위를 기록한다. 대화로 만든 경험 메모는 사용자 제공 내용을 확인해 저장한다. 원문, 사용자 제공 자료와 AI가 만든 발췌·정리본을 명확히 구분한다. URL만 기록한 파일은 본문을 읽은 자료로 간주하지 않는다.
- 브라우저 AI가 접근한 내용을 정리했다면 원문이 아닌 AI 작성 중간 자료로 표시한다. 보이는 자료의 범위와 출처를 남기고 사람이 원문과 대조할 수 있게 한다.
- 저장 또는 자료 접근이 불가능하면 원인을 알리고 대안을 제안한다. 해당 자료의 분석을 보류한다.
- 수강생의 실습 기록·결과는 `outputs/` 아래 작업별 폴더에 `{YYYYMMDD_HHMM}_{작업명}_{모델명}_{작업번호}.{확장자}`로 저장한다. `YYYYMMDD_HHMM`은 확인한 현재 날짜와 24시간제 시각을 쓴다. 모델명은 실행 환경에서 확인하고, 못 하면 사용자에게 한 번 묻는다. 그래도 모르면 추측하지 말고 `모델미확인`으로 적는다. 날짜·시각을 확인하지 못하면 `시각미확인`으로 적는다. 작업번호는 `01`부터 시작하며 같은 이름이 있으면 번호를 높인다. 수정본도 새 파일로 구분한다.

## 에이전트 작업 기록과 인계

- 파일을 생성하거나 수정한 작업은 `agents_logs/YYYY-MM-DD-모델이름/progress-log.md` 하나에 진행 상황·변경 내역·결정·검증 결과를 누적한다. 날짜와 모델명은 실제 실행 환경에서 확인해 쓴다. 도구 이름과 모델명을 혼동하거나 모델명을 지어내지 않는다. 확인할 수 없으면 사용자에게 묻고, 그래도 모르면 폴더 이름에 `모델미확인`을 쓴다. (예: `2026-11-13-모델미확인`)
- 로그 안에 `## HH:MM — 작업명` 제목으로 각 작업을 구분한다. 실제 작업 시각을 확인해 기록하고, 확인하지 못하면 추측하지 않는다. 관련 제목과 구간부터 찾아 읽는다.
- 에이전트의 관련 작업 산출물은 같은 날짜·모델 폴더에 작업별로 구분해 둔다. 수강생 실습 결과는 `outputs/`에 둔다. 실제로 사용될 프로젝트 파일은 지정된 위치에 만들거나 수정하고 기록에 그 경로를 남긴다. 기록용 복사본을 무조건 만들지는 않는다.
- 새 대화나 새 요청에서는 `agents_logs/INDEX.md`를 먼저 읽고 아래 "새 작업인지 이어가는 작업인지 판단"에 따른다. 로그 전체는 읽지 않고 관련 작업의 제목과 구간만 읽는다. 기록이 없으면 바로 진행한다. 이어갈 작업은 목표·범위·완료 및 미완료 상태·결정·산출물 경로·검증 근거·장애물·가정·다음 행동을 `progress-log.md`에 간결히 남긴다. 재개할 때는 기록을 출발점으로 삼고 관련 파일과 외부 상태를 다시 확인한 뒤 진행한다.

## 새 작업인지 이어가는 작업인지 판단

`agents_logs/INDEX.md`는 작업 하나가 한 줄인 색인이다. 파일이 없거나 표가 비어 있으면 모든 요청은 새 작업이다. 파일을 읽을 수 없는 환경이면 사용자에게 지난 작업이 있는지 묻는다.

| 상황 | 판단 | 하는 일 |
| --- | --- | --- |
| 사용자가 "이어서", "지난번"이라고 하거나 `진행 중`인 작업과 주제가 같다 | 이어가기 | 그 작업의 로그 구간과 `outputs/` 최신 파일을 읽고 관련 파일과 외부 상태를 다시 확인한 뒤 `다음 행동`부터 진행한다 |
| 같은 작업에 새 자료나 수정 요청이 온다 | 갱신 | 이전 결과는 보존하고 새 파일(작업번호 +1)을 만든다. 달라진 점을 로그에 남긴다 |
| 맞는 작업이 없다 | 새 작업 | 새 작업명으로 시작하고 `INDEX.md`에 한 줄 추가한다 |
| 비슷한 작업이 둘 이상이거나 애매하다 | 확인 | "이어서 / 새로 / 새 자료로 갱신" 중 사용자가 고르게 한다. 추측해서 기존 작업을 덮어쓰지 않는다 |

- `INDEX.md`의 열은 작업명·상태·마지막 날짜·결과 위치·로그 위치·다음 행동이다. 상태는 `진행 중`, `완료`, `보류` 중에서 적는다. 작업이 생기거나 상태가 바뀔 때만 해당 줄을 고치고, 새 작업은 표 맨 아래에 추가한다.
- 색인은 모델별 폴더 밖에 있어서 수강생이 다른 AI로 바꿔도 이어갈 수 있다. 이어가는 작업을 현재 날짜·모델 폴더의 로그에 새로 기록할 때는 첫 줄에 `이전 기록: <경로>`를 남기고, 색인의 `로그 위치`는 가장 최근 기록으로 고친다.
- `완료`인 작업을 다시 열면(수정·새 자료) 상태를 `진행 중`으로 바꾸고 `다음 행동`을 고친다.
- 로그에는 개인정보와 자료 본문을 적지 않고 경로와 요약만 적는다.
- 로그 파일이 20KB를 넘으면 오래된 항목을 같은 폴더의 `progress-log_보관.md`로 옮기고 요약을 남긴다. 삭제하지 않는다.
- `INDEX.md`의 `완료` 항목이 10줄을 넘으면 오래된 완료 항목부터 `agents_logs/INDEX_보관.md`로 옮기고, 색인 표 아래에 `보관: agents_logs/INDEX_보관.md (n건)` 한 줄을 남긴다. `진행 중`·`보류`는 옮기지 않는다. 보관된 작업을 다시 열면 그 줄을 색인으로 되돌리고 상태를 `진행 중`으로 바꾼다. 삭제하지 않는다.

## 작업 보고

계획·결과는 `예정`, `완료`, `확인`처럼 짧게 보고하고 설명·질문은 자연스러운 존댓말을 쓴다. 파일 작업 후 다음 두 줄에 실제 확인 내용과 생성·수정한 파일 경로를 모두 적는다. 없으면 `없음`, 확인하지 못했으면 `미확인`으로 표시한다. 단순 질문·대화에는 이 형식을 강요하지 않는다.

> - **상태**: `<작업 요약>` | **작업 기록**: `<작업 기록 경로 또는 없음>`
> - **산출물**: `<생성·수정한 파일 경로 또는 없음>` | **검증**: `<실제 확인 내용 또는 미확인>`
