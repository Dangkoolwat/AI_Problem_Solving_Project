# 워크플로우를 함께 만들고 다시 사용하기

워크플로우는 목표를 이루기 위해 필요한 자료·작업·확인을 연결한 흐름이다. 사용자가 이론을 읽는 데 그치지 않고 직접 선택하고 실행하며 바꿔 볼 수 있게 돕는다. 주제와 결과물을 고정하지 않고 하나의 에이전트가 필요한 로컬 스킬과 실제 사용 가능한 도구를 조합한다. 여러 스킬을 쓴다는 뜻이 여러 에이전트의 병렬 실행이나 자동 감시는 아니다.

## 1. 고민을 듣고 계획 세우기

- 사용자의 이야기와 기존 자료·대화를 먼저 살핀다. 목표와 방법이 모호하면 필요한 질문을 한 번에 1~2개씩 나누고, 상황에 맞는 방법과 각각 얻을 결과를 쉽게 제안한다. 이미 정한 내용은 다시 고르게 하지 않는다.
- 목표, 필요한 자료와 준비 방법, 단계별 결과, 에이전트가 할 일과 사람이 선택·확인할 일, 활용할 스킬·도구, 확인이 필요한 조건을 계획으로 보여 준다. 어떤 방법을 엮을지는 `instructions/방법_메뉴.md`에서 후보를 찾는다. 스킬 이름보다 사용자가 실제 무엇을 얻게 되는지 먼저 설명한다. 이미 준비된 자료와 없는 자료를 구분한다.
- 사용자가 중요하게 여기거나 자료·판단·제작이 복잡한 작업이면 모델 선택도 함께 돕는다. 현재 환경에서 실제 확인 가능한 모델과 작업에 필요한 입력·도구, 수강생의 사용 조건과 비용·속도·난이도를 살펴 적합한 모델 또는 비교할 선택지를 제안하고 이유를 쉽게 설명한다. 간단한 일에는 매번 모델 변경을 권하지 않는다.
- 모델 목록·요금·성능·무료 사용 범위는 바뀔 수 있으므로 현재 화면이나 공식 정보를 확인한 범위와 날짜를 밝힌다. 계정별 선택 가능 여부나 성능을 확인할 수 없으면 미확인으로 두고 수강생이 직접 선택할 수 있게 안내한다. 모델과 검색·파일·이미지 생성 등 도구의 사용 가능 여부는 따로 확인한다. 이미 사용자가 정한 모델을 존중하며 자동으로 바꾸지 않는다.
- 진행 방식이 정해지지 않았다면 **한 단계씩 함께하기**와 **계획 승인 후 가능한 단계 이어서 하기** 중 선택하게 한다. 하나만 고정하지 않으며 언제든 바꿀 수 있다. 사용자가 방식을 이미 말했다면 다시 묻지 않는다.
- 계획을 사용자가 수정하거나 승인할 수 있게 보여 준다. 새로 구성한 여러 단계 워크플로우는 사용자의 승인을 받은 범위에서 실행한다. 이미 구체적인 계획을 승인한 경우에는 같은 승인을 반복하지 않는다. 간단한 질문이나 한 번의 명확한 요청에 불필요하게 워크플로우 승인 절차를 끼워 넣지 않는다.

## 2. 확인하며 실행하기

- **한 단계씩 함께하기:** 해당 단계를 수행하고 결과와 확인할 내용을 보여 준 뒤 사용자가 다음 단계나 수정을 선택하게 한다.
- **이어서 수행하기:** 승인된 계획 안에서 사용 가능한 단계를 순서대로 수행하고 결과와 확인할 내용을 정리해 보여 준다. 이미 받은 선택을 되묻지 않는다. 사람의 결정이 필요한 지점이나 자료 접근·저장 불가로 진행할 수 없는 지점은 알리고 대안과 가능한 독립 작업을 제시한다.
- 확보한 원본은 `source/`에 보관하고, 분석할 자료는 `data/`에 저장해 읽을 수 있는지 확인한다. 결과와 사용자 경험은 `outputs/`에 저장한다. `instructions/자료_마련과_저장.md`와 `instructions/파일_저장_및_인계.md`를 따른다. 사실·해석·제안과 직접 확인한 내용을 구분한다.
- 계획 승인은 표시된 작업 범위에 대한 것이다. 외부 발송·공유, 설치 등 별도의 명시적 지시가 필요한 행동은 기존 지시와 실제 권한을 확인한 뒤 수행한다. 실제 스킬 로딩·검색·파일 생성 여부를 확인하기 전에는 완료했다고 말하지 않는다.

## 3. 저장하고 다음에 다시 사용하기

- 사용자가 워크플로우 저장을 요청하거나 승인한 계획에 저장이 포함된 경우, `templates/01_문제해결_업무지도.md`를 필요할 때 활용해 `outputs/`의 해당 작업 폴더에 Markdown으로 남긴다. 결과 파일명은 `instructions/파일_저장_및_인계.md`를 따른다.
- 기록에는 목표, 다음에 바꿀 자료, 유지할 단계와 사용할 스킬·도구, 사람과 에이전트의 역할, 결과 위치, 사람이 확인할 점, 실행 방식과 다시 요청할 말을 필요한 만큼 담는다. 모델을 추천하거나 사용했다면 실제 확인한 모델과 선택 이유·확인 시점, 미확인 사항을 구분해 남길 수 있다. 실제 선택·확인·수행과 제안·미확인을 구분하고 불필요한 개인정보나 인증정보는 적지 않는다.
- 다시 요청받으면 저장된 흐름과 관련 기록을 읽고 새 자료·원하는 결과·현재 도구와 접근 권한을 확인한다. 저장된 지침이나 이전 결과가 현재 사실이라고 단정하지 않는다. 바뀐 자료와 적용할 단계를 알려 주고 수정·승인을 받은 뒤 실행한다. 같은 계획을 이미 승인했다면 반복해서 묻지 않는다.
- 원본과 이전 결과를 보존하고 새 결과와 변경점을 구분한다. 필요하면 `.skills/update-workflow/SKILL.md`를 함께 읽는다. 자동 예약·알림이나 스킬 자동 로딩은 별도 기능과 실제 확인 없이 가정하지 않는다.
- 예약 실행이나 텔레그램 등 휴대폰 전달은 안내 문서에 실린 예시일 뿐 정해진 방법이 아니다. 사용자가 이를 요청하거나 궁금해하면 바로 설정하지 않고, 원하는 목적·주기·받고 싶은 형태를 한 번에 1~2개씩 먼저 묻는다. 현재 환경에서 확인한 가능 여부를 바탕으로 맞는 방법과 더 간단한 대안에 대한 의견을 이유와 함께 제시하고, 사용자가 고르게 한다.
