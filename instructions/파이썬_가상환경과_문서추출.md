# Python 가상환경과 문서 추출 안내

이 안내는 PDF·문서 추출, OCR 또는 다른 작업에 Python 환경이 필요할 때 에이전트가 읽는다. 학습자가 터미널 명령을 외우거나 직접 실행해야 하는 것은 아니다. 먼저 목적과 사용 가능한 도구를 확인하고, 쉬운 말로 할 일과 확인 방법을 알린다.

## 1. 기존 도구와 자료부터 확인

- 현재 환경에서 사용할 수 있는 문서 읽기·변환·OCR 도구와 이미 설치된 Python·관련 패키지를 확인한다. 해당 작업에 쓸 수 있는 기존 도구가 있으면 그것부터 활용한다. Python이나 별도 설치가 항상 필요한 것은 아니다.
- PDF에 선택 가능한 글자가 있는지와 작업에 필요한 페이지·표·그림·수식이 무엇인지 살핀다. 텍스트 추출이 부족한 스캔본은 OCR이나 사람이 제공한 자료 등 실제 가능한 대안을 설명한다. 외부 OCR로 자료를 보낼 경우 전송 범위·비용·권한을 확인하고 사용자의 명시적 지시를 따른다.
- 이전에 같은 원본에서 만든 추출본이 있으면 원본과 추출 범위·상태를 확인해 재사용할 수 있다. 이름이 같다는 이유만으로 최신 자료나 완전한 추출이라고 단정하지 않는다.

## 2. Python 환경이 필요한 경우

- 운영체제와 작업공간, 사용할 Python 실행 파일과 버전, 기존 `.venv`와 필요한 패키지의 사용 가능 여부를 확인한다. 다른 프로젝트의 가상환경이나 시스템 Python에 임의로 패키지를 설치하지 않는다.
- 새 가상환경은 작업공간 안의 `.venv`를 기본 후보로 삼되 기존 폴더가 있으면 내용을 덮어쓰거나 지우지 않는다. 생성 위치와 권한을 확인하고 작업의 영향 범위를 알린다. 패키지 설치·변경이나 Python 자체 설치는 사용자의 명시적 허가가 있을 때만 한다. 이미 허가받은 작업은 다시 묻지 않는다.
- Python이 있고 새 `.venv`가 없는 경우, 사용 가능한 실행 파일을 확인한 뒤 운영체제에 맞게 표준 `venv`를 사용한다. 다음은 작업공간을 현재 위치로 지정했을 때의 예시이며 실행 여부는 환경과 지시에 따른다.

  ```text
  Windows: py -3 -m venv .venv
  macOS:   python3 -m venv .venv
  ```

  Windows의 `py`가 없거나 `python3`를 사용할 수 없으면 실제 확인된 Python 실행 파일을 사용한다. Python 자체가 없으면 설치를 임의로 진행하지 않고 상황과 대안을 알린다. `--clear`로 기존 환경을 지우거나 사용자 파일을 복구 없이 정리하지 않는다.

- 활성화에 의존하지 않고 가상환경의 Python을 직접 실행할 수 있다. Windows 예시는 `.venv\Scripts\python.exe`, macOS 예시는 `.venv/bin/python`이다. 경로에 공백이 있으면 적절히 따옴표로 감싼다. 실제 실행 파일과 버전을 확인하고, 패키지가 필요하다면 허가된 범위에서 그 Python의 `-m pip`를 사용한다. 전역 Python·공유 설정과 사용자 환경 변수는 바꾸지 않는다.
- 필요한 변환기나 OCR의 설치 방법·추가 구성·호환성은 해당 도구의 공식 안내와 실제 환경을 확인한다. 설치 전 필요한 패키지, 네트워크 사용 및 비용 가능성을 설명한다. 설치 실패를 숨기지 않으며 동일 오류가 반복되면 프로젝트 규칙에 따라 중단하고 대안을 알린다.

### requirements.txt로 필요한 패키지 관리

작업공간 루트의 `requirements.txt`는 PDF의 Markdown 변환에 필요한 `markitdown[pdf]`와 이미지 문자 인식을 호출하는 `pytesseract` 버전을 기록한다. 이 파일은 패키지 목록이며 실행하거나 설치했다는 뜻은 아니다. 적힌 MarkItDown 버전은 Python 3.10 이상, 3.15 미만이 필요하므로 가상환경을 만들기 전에 실제 버전을 확인한다.

기존 도구를 사용할 수 없어 패키지 설치가 필요하고 설치가 명시적으로 허가된 경우에만, 작업공간을 현재 위치로 지정하고 해당 운영체제의 가상환경 Python으로 설치한다.

```text
Windows: .\.venv\Scripts\python.exe -m pip install -r requirements.txt
macOS:   ./.venv/bin/python -m pip install -r requirements.txt
```

설치 후 같은 가상환경에서 패키지와 PDF 변환 가능 여부를 확인한다. `pytesseract`는 OCR 엔진을 호출하는 Python 패키지이며, **Tesseract 엔진과 필요한 언어 데이터는 별도로 준비해야 한다**. 스캔 PDF는 페이지를 이미지로 변환해 OCR을 수행할 수 있지만, 실행 환경과 도구를 확인하고 실제 결과를 시험해야 한다. 엔진·언어 데이터 설치나 외부 전송은 필요한 범위와 사용자 허가를 확인한다. 추출 결과를 원문과 대조하기 전에는 성공했다고 단정하지 않는다.

## 3. PDF 추출과 확인

- 확보한 PDF 원본은 `source/`에 보존한다. 분석할 추출본은 `data/`의 작업별 폴더에 저장하고 읽을 수 있는지 확인한다. 변환 도구·날짜·원본 위치·실제 처리한 범위와 오류를 기록한다. 원본과 추출본을 구분하며 기존 파일은 덮어쓰지 않는다.
- Microsoft [MarkItDown](https://github.com/microsoft/markitdown)은 가능한 변환 도구 중 하나다. 설치·PDF 지원·OCR 사용 가능 여부는 현재 환경에서 확인한다. 이미지 인식이나 외부 서비스가 별도 구성일 수 있으므로 기본 설치만으로 스캔본이 처리된다고 가정하지 않는다.
- 처음·중간·끝 등 관련 페이지의 추출 내용과 원본을 대조한다. 누락된 페이지, 읽기 순서, 표·수식·그림과 특수문자를 확인할 수 있는 범위에서 살피고 문제는 기록한다. PDF 화면의 페이지 번호와 책에 인쇄된 쪽수가 다를 수 있으므로 실제 확인하지 않은 페이지를 만들지 않는다. 추출이 불완전하거나 읽을 수 없으면 해당 부분의 분석을 보류하고 OCR·원문 확인 등 대안을 제안한다.
- 전체 추출본이 필요하면 보존하고, 단원별 학습 메모·핵심정리·퀴즈는 별도로 만든다. AI 요약과 원문 추출을 섞지 않는다. 토큰이나 비용 절감은 실제 측정 없이 수치로 단정하지 않는다.

참고: [Python `venv` 문서](https://docs.python.org/3/library/venv.html), [Microsoft MarkItDown](https://github.com/microsoft/markitdown), [pytesseract](https://github.com/madmaze/pytesseract).
