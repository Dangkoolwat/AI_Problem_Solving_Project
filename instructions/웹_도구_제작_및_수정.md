# 웹 도구 제작과 수정

대시보드, 간단한 웹 도구나 코드를 만들고 고칠 때 읽는다. 사용자가 개발을 몰라도 목적과 선택지를 이해하고 결과를 확인할 수 있게 돕는다. 이 안내는 [Karpathy Guidelines](https://github.com/multica-ai/andrej-karpathy-skills/blob/main/skills/karpathy-guidelines/SKILL.md)의 네 가지 코딩 원칙을 참고해 이 작업공간에 맞게 구성했다.

## 1. 만들기 전 생각하기

- 어떤 문제를 풀고 누가 무엇을 볼지, 필요한 자료와 결과·확인 방법을 짧게 정리한다. 확실하지 않은 내용은 사실처럼 정하지 않는다.
- 선택에 중요한 정보가 부족하면 한 번에 1~2개씩 묻는다. 간단한 가정으로 안전하게 진행할 수 있다면 그 가정과 선택지를 알리고 진행한다.
- 파일 생성·수정 전에 할 일과 확인 방법을 짧게 알린다. 중요한 조건이 갖춰지면 불필요한 승인 질문 없이 진행한다. 삭제·게시·설치 등은 공통 권한 규칙을 따른다.

## 2. 작고 단순하게 만들기

- 선택한 목표를 충족하는 가장 단순한 결과부터 만든다. 요청하지 않은 기능·설정·복잡한 구조는 추가하지 않는다.
- 자료와 도구가 실제로 사용 가능한지 확인하고, 불가능하면 알리고 대안을 제시한다. 수치나 자료를 지어내지 않고 확인할 수 없는 내용은 `[확인 필요]`로 구분한다.
- 사용 방법을 비개발자도 이해할 수 있게 설명한다. 인터넷이나 별도 프로그램이 필요한 결과라면 그 조건을 알린다.

## 3. 필요한 범위만 고치기

- 수정 전 현재 파일과 문제에 연결된 부분을 확인한다. 사용자가 요청한 문제를 해결하는 데 필요한 부분만 바꾸고 관련 없는 내용·기존 검증과 오류 처리를 보존한다.
- 한 곳의 수정이 연결된 화면이나 기능에 영향을 주는지 살펴보고 필요한 부분도 함께 고친다. 사용자 자료와 이전 결과는 보존하고 저장·수정본 구분은 `instructions/파일_저장_및_인계.md`를 따른다.
- 범위를 넓혀야만 해결되거나 다른 사람의 변경과 충돌하면 상황을 설명한다. 삭제·설치·게시를 임의로 하지 않는다.

## 4. 목표에 맞게 확인하기

- 시작할 때 결과의 확인 기준을 정한다. 예를 들어 원본 숫자와 표가 맞는지, 버튼을 누르면 기대한 화면이 나오는지, 자료가 없을 때도 안내가 보이는지 살핀다.
- 가능한 범위에서 실제 자료·화면·주요 동작을 확인하고, 수정한 부분과 영향을 받는 부분을 점검한다. 필요한 범위에서 오류 처리·접근성·자료 보호를 유지한다.
- 파일 내용만 확인한 것과 브라우저에서 직접 열어 조작한 것을 구분한다. 확인할 수 없는 동작은 `미확인`으로 남기고 사용자가 확인할 방법을 쉽게 안내한다. 확인하지 않은 일을 완료했다고 말하지 않는다.
- 오류가 나면 원인을 살펴 조정하고, 동일한 오류가 두 번 발생하면 해당 작업을 멈춰 상황과 대안을 알린다. 무관하게 안전하게 진행할 수 있는 일은 이어간다.

## 마무리

무엇을 만들거나 고쳤는지, 실제로 확인한 것과 남은 확인을 짧게 알린다. 사용자가 직접 점검하고 수정 요청을 선택하도록 돕는다. 저장·작업 기록과 보고는 `instructions/파일_저장_및_인계.md`를 따른다.
