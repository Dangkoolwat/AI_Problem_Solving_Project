# 생각 넓히기

> 이 파일은 `.skills/thinking-toolkit/SKILL.md`의 방법별 안내다. 공통 원칙은 SKILL.md를 먼저 읽는다.

**언제:** 아이디어가 떠오르지 않거나, 같은 생각만 맴돌거나, 가진 아이디어가 밋밋하게 느껴질 때. 이미 선택지가 충분하면 쓰지 않는다.

## 상황에 맞게 고르기

| 상황 | 방법 | 얻는 결과 | 아쉬운 점 |
| --- | --- | --- | --- |
| 아이디어가 아예 없다, 문제를 한 가지로만 보고 있다 | 문제 다시 정의하기 | 다르게 적은 문제 문장 서너 개와 각각에서 나온 방향 | 바로 쓸 아이디어는 적을 수 있다 |
| 아이디어는 있는데 밋밋하다 | 스캠퍼 | 일곱 가지 렌즈로 바꿔 본 아이디어 | 기존 아이디어가 있어야 한다 |
| 뻔한 답만 나온다 | 뻔한 답 빼고 받기, 대상 바꿔 보기 | 평소라면 떠올리지 않을 아이디어 | 현실성이 낮은 것이 섞인다 |
| 같은 분야 안에서만 맴돈다 | 다른 분야에서 빌려오기 | 다른 분야의 원리를 내 문제에 옮긴 아이디어 | 억지스러운 연결이 나올 수 있다 |

둘 이상을 이어 써도 된다. 맞아 보이는 하나를 의견과 이유로 먼저 밝힌다.

## 문제 다시 정의하기

같은 문제를 다른 문장으로 적어 본다. 필요한 것만 고른다.

- **뒤집기:** "어떻게 하면 잘될까" 대신 "어떻게 하면 확실히 안 될까"를 적고 거꾸로 읽는다.
- **넓히거나 좁히기:** 더 큰 목적은 무엇인지, 가장 작은 한 장면은 무엇인지로 범위를 바꾼다.
- **증상과 원인 나누기:** 지금 문제가 겉으로 보이는 증상인지, 그 아래 원인이 따로 있는지 본다.
- **시점 바꾸기:** 이번 주의 문제로 볼 때와 1년 뒤의 문제로 볼 때 무엇이 달라지는지 본다.

다시 적은 문장마다 떠오르는 방향을 한 줄씩 붙인다. 사용자가 마음에 드는 문장을 고른다.

## 스캠퍼 (SCAMPER)

이미 있는 아이디어 하나를 일곱 가지 렌즈로 바꿔 본다. 일곱 개를 모두 채울 필요는 없고, 잘 맞는 서너 개만 써도 된다.

| 렌즈 | 묻는 것 |
| --- | --- |
| 바꾸기 | 재료·사람·장소·시간 중 하나를 다른 것으로 바꾸면? |
| 합치기 | 다른 아이디어나 활동과 합치면? |
| 가져오기 | 비슷한 일에서 쓰던 방식을 가져오면? |
| 고치기 | 크기·횟수·순서·모양을 키우거나 줄이면? |
| 다르게 쓰기 | 다른 사람이나 다른 목적에 쓰면? |
| 빼기 | 무엇을 없애면 더 단순해질까? |
| 뒤집기 | 순서나 역할을 반대로 하면? |

## 뻔한 답 빼고 받기, 대상 바꿔 보기

- 누구나 떠올릴 답을 먼저 적어 제외하고, 그 밖의 아이디어를 다섯 개쯤 받는다.
- 대상을 바꿔 본다. 대학생 대신 은퇴한 사람, 신입 대신 10년 차처럼 다른 사람이 쓴다면 무엇이 필요한지 본다.

## 다른 분야에서 빌려오기

전혀 다른 분야 두세 곳을 고른다. 분야마다 그곳에서 비슷한 문제를 푸는 원리를 한 줄로 적고, 내 문제에 옮기면 어떤 행동이 되는지 붙인다. 분야는 사용자가 고르거나 에이전트가 제안한다.

## 지켜 줄 것

- 넓히는 동안에는 평가하지 않는다. 다 모은 뒤에 고른다.
- 에이전트가 낸 아이디어는 제안이다. 사용자가 한 일이나 확인된 사실처럼 기록하지 않는다.
- 다른 분야의 원리나 사례를 사실로 인용할 때는 확인한 것만 쓰고, 확인하지 못했으면 "이런 식의 원리"라고 밝힌다.
- 효과나 성공 가능성을 숫자로 말하지 않는다.
- 아이디어를 많이 내는 데서 끝내지 않는다. 마지막에 사용자가 두세 개를 고르게 한다.

**결과:** 넓힌 아이디어 목록과 사용자가 고른 두세 개.

**사용자가 더 원하면:** 고른 것을 비교하려면 `06_가정과_선택_비교.md`, 위험을 보려면 `07_미리_어려움_살펴보기.md`로 잇는다. 기획안을 만드는 중이면 `.skills/planning-toolkit/SKILL.md`로 돌아간다.
