# 함께 기획하고 결과 만들기

수강생의 구상이나 이미 작성된 자료에서 시작한다. 먼저 기존 대화·기록과 제공된 내용을 살펴 목표, 대상, 독자, 사용 가능한 자료와 원하는 결과 중 이미 정해진 것을 확인한다. 결정에 필요한 내용만 한 번에 1~2가지씩 묻고, 막히면 상황에 맞는 방법과 각 결과를 예로 보여 준다. 사용자가 하나나 여러 방법을 고르거나 다른 방향을 말할 수 있다. 요청이 없어도 지금 상황에 맞아 보이는 방법 하나를 의견과 이유로 짧게 밝히고, 선택은 사용자에게 맡긴다.

## 상황에 맞게 흐름 고르기

아래는 기획을 돕는 선택지이며 고정 순서가 아니다. 이미 초안이나 명확한 목표가 있으면 그 지점에서 시작한다. 모든 기획에 고객 인터뷰·KPI·보고서·PPT를 강요하지 않는다.

1. **문제와 아이디어:** 누구의 어떤 상황을 바꾸고 싶은지, 현재 확인된 사실과 아직 모르는 점을 나눈다. 대안을 생각할 때 장점과 제약, 각 방법으로 얻을 결과를 쉽게 제안한다. 사용자가 결정한다.
2. **자료 마련과 분석:** 자료가 필요하면 `instructions/자료_마련과_저장.md`에 따라 저장하고 읽을 수 있는지 확인한 뒤 분석한다. `research-toolkit`, `data-toolkit`, `evidence-check`를 필요할 때 함께 활용한다. 자료가 없으면 목표를 이야기하며 함께 준비할 수 있다.
3. **구조 잡고 초안 만들기:** 사용자가 제공한 양식이 있으면 우선한다. 그렇지 않으면 배경·문제·대상·목표·제안·실행·확인할 점 중 필요한 항목을 고른다. 기획서·제안서의 첫머리를 논리적으로 열고 싶다면 상황 → 변화·문제 → 핵심 질문 → 제안 순서로 열 수 있다(기획서 첫머리 열기). `templates/06_기획_초안.md`는 선택형이다. 가설과 기대 효과는 확인된 사실·성과와 구분하고, 근거 없는 일정·예산·인원·목표치를 만들지 않는다. 수치가 없어도 관찰할 변화나 확인 방법을 정할 수 있다.
4. **관점과 위험 살피기:** 사용자가 원하거나 기획 판단에 도움이 될 때, 기획안을 비판적으로 살펴볼지 먼저 제안한다. 예를 들어 대상자·담당자·결정권자 관점, 실패를 가정한 사전 점검, 대안 비교 중 고를 수 있다. 질문은 한 번에 필요한 만큼 나누고 사람을 몰아붙이지 않는다. 확인한 문제와 가능한 위험을 구분하고, 근거·영향·확인 방법·대응 선택지를 보여 준다. AI가 반론을 제시한 것만으로 실제 검증이 끝났다고 말하지 않는다.
5. **완성·전달·다시 활용:** 독자와 목적에 맞게 기획서, 짧은 보고서, 이메일·메신저 초안, 발표 자료 중 요청한 결과를 만든다. 모집글·소개글·제안서·안내문처럼 읽는 사람의 행동을 이끌어야 할 때는 `persuasion-writing`을 함께 활용할 수 있다. 논리적 배경·문제의식으로 기획을 열 때는 이 스킬을 쓰고, 공감으로 참여·승인을 이끌 때는 `persuasion-writing`을 쓴다. Markdown 기획 초안을 보관하고 필요한 경우 사용할 수 있는 문서·발표 도구로 DOCX·PPT를 만든다. 사용자가 지정한 템플릿과 기존 파일을 우선 확인한다. 중요한 내용은 원문과 대조하고, 문서·슬라이드의 실제 렌더링이 가능할 때 확인한다. 공유·발송은 명시적 지시와 권한을 따른다. 새 자료가 오면 `update-workflow`로 이전 결과와 변경점을 연결한다.

## 기획 종류에 따라 달라지는 질문

| 기획 | 먼저 살펴볼 것 | 필요할 때 덧붙일 것 |
| :--- | :--- | :--- |
| 서비스·기능 | 누가 어떤 상황에서 겪는 문제인지 | 해결 방법, 사용 흐름, 확인 방법 |
| 행사·마케팅 | 누구에게 무엇을 알리거나 경험하게 할지 | 일정·장소·홍보·운영·예산 |
| 사업·제휴 제안 | 상대가 얻을 가치와 요청할 결정 | 역할·조건·실행 가능성·근거 |
| 내부 업무 개선 | 현재 과정과 불편한 지점 | 변경 전후 흐름·담당·적용 조건 |
| 학습·지역 활동 | 참여자의 관심사와 바라는 경험 | 준비물·진행 방식·참여자 피드백 |

종류는 예시다. 목적에 맞으면 섞거나 다른 구성을 사용한다. 자료가 부족하면 `[확인 필요]`로 남기고, 수강생이 선택·확인한 내용과 AI의 아이디어를 구분한다.

## 참고 원본과 프로젝트에 맞춘 사용

이 스킬 폴더의 `references/upstream/superpowers/skills/brainstorming/SKILL.md`와 `references/upstream/mattpocock-skills/skills/productivity/grilling/SKILL.md`는 질문·대안 탐색과 가정 점검에 필요할 때 읽는다. 원본의 개발 전용 절차, 강한 질문 방식, 별도 문서 승인·하위 에이전트·스크립트 실행은 그대로 강제하지 않는다. 원본에 포함된 스크립트는 환경과 사용자 지시를 확인하기 전 실행하지 않는다.
