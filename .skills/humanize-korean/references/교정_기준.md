# 교정 기준

> 이 파일은 `.skills/humanize-korean/SKILL.md`의 세부 안내다. 공통 원칙은 SKILL.md를 먼저 읽는다.

글에 실제로 나타나는 것만 골라 고친다. 아래 표현이 한두 번 나왔다고 모두 없애지 않으며, "그대로 두는 때"에 해당하면 고치지 않는다. 고치는 정도가 1)이면 이 파일의 기준을 적용하지 않는다.

## 1. 번역투와 조사

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| "~적", "~의", "~것"이 겹침 | "사회적 문제" → "사회 문제", "문제의 해결" → "문제 해결", "내가 생각하는 것은" → "내 생각은" | "사회적 거리"처럼 굳은 말, 빼면 뜻이 달라지는 경우 |
| "~를 통해", "~에 있어서", "~에 대해" | "프로젝트를 통해 경험을 했습니다" → "프로젝트에서 경험했습니다", "기획에 있어서" → "기획에서", "일정에 대해 논의" → "일정을 논의" | 수단이나 경로를 실제로 뜻할 때, 한 문단에 한두 번일 때 |
| "~을 가지고 있다" | "강한 책임감을 가지고 있습니다" → "책임감이 강합니다" | 물건을 실제로 가지고 있다는 뜻일 때 |
| "~할 수 있다"의 반복 | "효율을 높일 수 있습니다" → "효율을 높입니다" | 가능성이나 허락을 말해야 할 때 |
| "~에서의", "~으로의" 같은 겹친 조사 | "현장에서의 경험" → "현장에서 한 경험" | 제목처럼 짧게 써야 할 때 |
| "그", "그녀", "그것", "그들"의 반복 | 주어를 생략하거나 이름·직함으로 바꾼다 | 가리키는 대상이 헷갈릴 때 |
| 꾸미는 말이 길게 겹친 명사 | 문장을 둘로 나눈다 | 나누면 뜻이 흐려질 때 |

## 2. 피동

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| 겹친 피동 | "보여지다" → "보이다", "되어지다" → "되다", "기대되어진다" → "기대한다" | 없음 |
| "~에 의해" | "이 책에 의해 깨달았다" → "이 책을 읽고 깨달았다" | 누가 했는지 모르거나 밝히지 않아야 할 때 |
| 사물이 주어인 문장 | "제공이 가능합니다" → "제공합니다", "회의가 진행됐습니다" → "회의를 했습니다" | 행위자보다 대상이 중요할 때 |

## 3. 완료·진행·예정 표현

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| "~해왔습니다", "~되어 왔습니다" | "노력해왔습니다" → "노력했습니다", "사용되어 왔습니다" → "사용됐습니다" | 과거부터 지금까지 이어졌다는 점이 중요할 때 |
| "~하고 있습니다", "~해오고 있습니다" | "준비하고 있습니다" → "준비합니다" 또는 "준비 중입니다" | 지금 실제로 하는 중인 일일 때 |
| "~할 예정입니다" | "방문할 예정입니다" → "방문하려고 합니다" 또는 "방문합니다" | 확정된 일정임을 밝혀야 할 때 |

## 4. 상투어와 과장

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| "결론적으로", "요약하면", "정리하자면" | 지우고 바로 내용을 쓴다 | 긴 글의 마지막 정리 한 번 |
| "시사하는 바가 크다", "주목할 만하다", "매우 중요하다" | 지우거나, 무엇이 왜 중요한지 원문에 있는 내용으로 쓴다 | 원문에 근거가 바로 이어질 때 |
| "혁신적인", "완벽한", "획기적인", "효율적이고 효과적인", "극대화" | 꾸미는 말을 덜고 원문의 행동과 사실만 남긴다 | 인용문이나 고유한 이름의 일부일 때 |
| "크게 세 가지로 나눌 수 있습니다", "다음과 같습니다" | 지우고 바로 내용을 쓴다 | 목록이 실제로 이어지는 안내문 |
| "~할 때입니다", "~에서 ~로", "~을 넘어 ~로" 식의 결말 | 무엇을 하겠다는 문장으로 쓴다 | 글 전체에 한 번 |
| "A가 아니라 B입니다", "A인가, B인가" 대구의 반복 | 한 번만 남기고 나머지는 평범한 문장으로 쓴다 | 한 번 |

꾸미는 말을 덜어 낼 때 원문에 없는 수치나 사례로 채우지 않는다. 구체적인 내용이 필요해 보이면 사용자에게 묻는다.

## 5. 완곡과 접속사

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| "~로 보입니다", "~로 판단됩니다", "~인 듯합니다"의 반복 | 확실한 내용은 "~입니다"로 쓴다 | 실제로 불확실한 내용일 때 |
| 겹친 완곡 | "가능성이 있을 수 있습니다" → "가능성이 있습니다" | 없음 |
| 문두의 "또한", "따라서", "즉", "나아가", "아울러" | 대부분 지우고 문장 순서로 흐름을 잡는다 | 앞뒤 관계가 접속사 없이는 드러나지 않을 때 |
| "이는", "이 점에서", "이러한" | 가리키는 말을 직접 쓰거나 지운다 | 지우면 무엇을 가리키는지 모를 때 |
| "~해야 합니다", "~할 필요가 있습니다"의 반복 | 누가 무엇을 하는지로 쓴다 | 규정이나 안내문 |

## 6. 문장과 리듬

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| 접속사로 세 번 넘게 이어진 긴 문장 | 뜻이 흐려지지 않게 두세 문장으로 나눈다 | 나누면 뜻이 달라질 때 |
| 같은 어미가 네 문장 넘게 이어짐 | 어미를 한두 곳 바꾼다 | 보고서의 개조식, 안내문의 항목 |
| 길이가 모두 비슷한 문장 | 이웃한 짧은 문장을 하나로 잇거나 긴 문장을 나눈다. 내용은 더하지 않는다 | 원문이 일부러 짧게 끊어 쓴 글 |
| "~고", "~며", "~지만" 바로 뒤의 쉼표 | 쉼표를 지운다 | 읽을 때 뜻이 헷갈리는 곳 |
| 같은 단어의 반복 | 한 번은 생략하거나 가리키는 말로 바꾼다 | 용어를 통일해야 하는 문서 |

## 7. 구조와 서식

원문의 서식은 사용자가 바꾸라고 하지 않으면 유지한다. 아래는 사용자가 흐름까지 고쳐 달라고 했거나(고치는 정도 4~6) 서식이 읽기를 방해할 때만 제안한다.

| 줄일 표현 | 고친 예 | 그대로 두는 때 |
| --- | --- | --- |
| 소제목 아래의 "~를 살펴보겠습니다" | 지운다 | 발표 대본 |
| 이어 쓰면 되는 내용을 잘게 나눈 목록 | 문단으로 잇는다 | 절차, 준비물처럼 목록이 맞는 내용 |
| 문장마다 들어간 굵은 글씨와 따옴표 강조 | 꼭 필요한 곳만 남긴다 | 원문 작성자가 일부러 넣은 강조 |
| 매번 붙는 괄호 영어 | 처음 한 번만 남긴다 | 영어 표기가 꼭 필요한 용어 |
| 줄표(—)로 붙인 덧말의 반복 | 쉼표나 별도 문장으로 푼다 | 원문에 처음부터 있던 줄표 |

## 8. 그 밖에 보는 것

- 오탈자, 띄어쓰기, 조사, 주어와 서술어의 호응
- 뜻이 분명하지 않은 문장. 뜻을 짐작해 고치지 않고 사용자에게 묻거나 확인할 항목에 적는다.
- 소리 내어 읽기 어려운 문장

## 고친 뒤 다시 볼 것

1. 이름, 날짜, 수치, 인용문이 원문과 같은가
2. 원문에 없던 내용, 비유, 꾸미는 말이 들어가지 않았는가
3. 말투 수준이 원문 또는 사용자가 고른 말투와 같은가
4. 글의 성격이 바뀌지 않았는가. 보고서가 블로그 글처럼, 개인 기록이 공문처럼 되지 않았는가
5. 고친 양이 고르기로 한 정도에 맞는가

하나라도 어긋나면 그 부분을 원문으로 되돌리고 다시 고친다.
