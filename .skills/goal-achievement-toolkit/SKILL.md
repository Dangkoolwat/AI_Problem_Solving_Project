# 목표와 실행 도구 상자

사용자의 고민과 이미 정한 목표·조건을 먼저 듣고 필요한 질문을 한 번에 1~2개씩 한다. 막힌 지점에 맞는 방법 하나나 몇 가지를 얻을 결과와 적용 이유를 붙여 쉬운 말로 제안한다. 사용자는 추천을 받아들이거나 다른 방법을 고르거나 직접 원하는 방식을 말할 수 있고, 방법·기간·기준·다음 행동을 바꾸거나 멈출 수 있다. 목표가 분명하면 불필요한 진단을 강요하지 않는다. 모든 방법을 쓰거나 정해진 순서로 적용할 필요는 없다.

| 원하는 도움 | 참고할 방법 | 얻을 수 있는 것 |
| --- | --- | --- |
| 무엇을 원하는지 막막하다 | 그로우 (GROW) | 바라는 것·현재 상황·선택지·다음 행동을 살피는 대화 |
| 관심사와 방향을 넓게 펼쳐 보기 | 만다라트 (Mandal-Art) | 중심 생각과 관련 아이디어를 나눈 그림. 모든 칸을 채울 필요는 없다. |
| 방향과 달라졌는지 볼 기준 정하기 | 목표와 핵심 결과 (OKR) | 목표와 확인할 수 있는 핵심 결과. 개인 상황에 맞게 단순화한다. |
| 막연한 목표를 구체화하기 | 스마트 목표 (SMART) | 구체성·확인 기준·실현 가능성·관련성·기한을 살핀 목표. 숫자와 기한은 유용할 때 함께 정한다. |
| 처음 해 보는 일이라 결과 목표가 부담스럽다 | 배우는 목표 (Learning Goal) | 합격·성과 대신 알아보거나 익히고 싶은 것을 구체적으로 적은 목표. 결과 목표를 버리라는 뜻은 아니다. |
| 정해진 결과나 일정까지 준비할 일을 나누기 | 역산 계획 (Backward Planning) | 원하는 결과에서 현재까지 거꾸로 정리한 준비 단계 |
| 특정 상황에서 어떤 행동을 할지 정하기 | 실행 의도 (Implementation Intention, If–Then) | “어떤 상황이면, 무엇을 하겠다”는 구체적인 대응 |
| 시작할 계기나 날을 고르기 | 새 출발 효과 (Fresh Start Effect) | 새 주·월·학기나 생일처럼 구분이 되는 날을 골라 그날 할 작은 첫 행동 하나. 효과가 짧을 수 있다. |
| 실천의 걸림돌 살피기 | 우프 (WOOP) | 바람·기대 결과·내적 장애물·그때 할 행동. 먼저 목표와 결과를 떠올리고 장애물과 대응 계획을 차례로 살핀다. |
| 반복할 행동을 생활에 연결하기 | 해빗 스태킹 (Habit Stacking) | 기존 행동 뒤에 작고 구체적인 새 행동을 연결하는 계획. 반복이 필요할 때만 쓴다. |
| 미루게 되는 일에 즐거움 붙이기 | 유혹 묶기 (Temptation Bundling) | 미루는 일을 할 때만 좋아하는 즐길 거리를 함께하는 계획. 효과가 시간이 지나며 줄 수 있다. |
| 해 본 계획을 점검하거나 바꾸기 | 돌아보기와 조정 | 실제 행동·도움·제약을 살펴 다음 행동이나 목표를 바꿀 선택지 |

고른 방법을 적용할 때 `references/방법별_활용.md`에서 해당 항목만 읽는다. 사용자가 원하면 방법을 조합하되 우프의 계획 단계와 실행 의도의 겹침을 설명하고 중복 질문을 줄인다. 계획보다 실행이 먼저 필요한 간단한 일은 바로 도울 수 있다.

## 원본을 참고할 때

- 스마트 목표와 돌아보기: `references/upstream/skillme/goals-accountability/SKILL.md`.
- 습관 연결: `references/upstream/skillme/habit-builder/SKILL.md`.
- 그로우 대화: `references/upstream/skillme/life-coach/SKILL.md`. 원본의 고정 점수·기한과 약속은 강제하지 않는다.
- 목표와 핵심 결과: `references/upstream/skillme/okr-builder/SKILL.md`. 팀·분기 중심 지침은 개인에게 강제하지 않는다.
- 우프: `references/upstream/woop/think-woop/SKILL.md`와 필요하면 같은 폴더의 `references/TEMPLATE.md`, `references/EXAMPLE.md`. 근거 설명은 `evidence/dossier.md`를 참고하되 효과 수치나 연구 결과는 원문 확인 전 단정하지 않는다.
- 원본 스킬이 없는 방법(만다라트·배우는 목표·역산 계획·실행 의도·새 출발 효과·유혹 묶기·돌아보기): `references/방법별_활용.md`와 거기에 적힌 출처만 참고한다.

원본은 읽을 참고 자료다. 공개 약속·다른 사람에게 공유·일정 등록·자동 추적, 고정 횟수·점수·기한, 특정 출력물을 강제하지 않는다. 습관이 정해진 기간에 형성된다고 보장하지 않는다. 외부 여건과 자원 제약도 인정한다. 우프에서는 내적 장애물을 사용자가 직접 고르도록 돕고, 외부 장애물을 개인 탓으로 바꾸지 않는다. 원본과 라이선스·버전은 `.skills/SOURCES.md`를 참고한다.

사용자가 원하면 목표, 이유, 다음 행동, 예상 장애물과 대응, 돌아볼 시점을 간결하게 정리한다. 수치·성과·완료를 지어내지 않으며, 아직 해 보지 않은 계획과 실제 행동을 구분한다. 기록이 필요하면 `instructions/파일_저장_및_인계.md`를 따르고, 이후 다시 왔을 때 실제로 확인한 내용만 반영한다. 자동 감시나 알림이 설정됐다고 말하지 않는다.

문제 자체를 살피거나 선택지를 비교할 때는 `.skills/thinking-toolkit/SKILL.md`, 행사·서비스 등 기획안을 다룰 때는 `.skills/planning-toolkit/SKILL.md`를 필요에 따라 함께 참고한다. 여러 단계의 재사용 워크플로우는 `instructions/워크플로우_구성과_재사용.md`를 따른다.
