# 이메일·메신저 답장 초안

> 이 파일은 `.skills/workplace-toolkit/SKILL.md`의 상황별 안내입니다. 공통 원칙은 SKILL.md를 먼저 읽습니다.

용건, 받는 사람과 관계, 원하는 말투와 전달 목적을 필요한 만큼 확인하고 이미 알려진 조건은 다시 묻지 않는다. 단순 확인, 거절·지연 알림, 후속 확인 등 상황에 맞는 제목과 초안을 제안하고, 근거 없는 약속·기한·승인은 추가하지 않는다. 사용자가 직접 확인하고 수정할 내용을 알린다. 외부 발송이나 공유는 별도의 명시적 지시와 사용 가능한 권한이 있을 때만 수행한다.

## 내놓을 선택지

아래는 출발점이다. 상황에 맞게 2~3개로 추려 얻는 결과·필요한 것·아쉬운 점을 한 줄씩 보여 주고, 맞아 보이는 하나를 의견과 이유로 먼저 밝힌다. 사용자가 이미 방법을 정했으면 다시 고르게 하지 않는다.

| 선택지 | 얻는 결과 | 필요한 것 | 아쉬운 점 |
| --- | --- | --- | --- |
| 짧고 분명하게 | 결론과 다음 행동만 담은 답장 | 하고 싶은 말 | 차갑게 읽힐 수 있음 |
| 사정 설명과 대안 제시 | 이유와 가능한 대안이 있는 답장 | 사용자가 줄 수 있는 대안 | 길어지고 약속이 늘 수 있음 |
| 먼저 확인 질문 | 답하기 전에 상대에게 물을 질문 | 빠진 정보 | 답이 한 번 더 늦어짐 |

**의견을 정하는 기준:** 받은 메일·메신저에 거절·지연을 알릴 때는 둘째, 단순 확인은 첫째, 요청이 모호하면 셋째를 권한다. 대안에는 사용자가 지킬 수 있다고 말한 날짜와 조건만 쓴다. 거절 이유와 대안을 따로 짜야 하거나 업무 범위·우선순위를 다시 나눠야 하면 `13_거절_일정조율.md`를 쓴다.

**결과 모습:** 제목과 초안, 보내기 전에 사용자가 확인할 점. 발송은 하지 않는다.
