# 틀린 문제 돌아보기 (오답 기록)

> 이 파일은 `.skills/learning-toolkit/SKILL.md`의 방법별 안내다. 공통 원칙은 SKILL.md를 먼저 읽는다.

**언제:** 문제는 푸는데 점수가 오르지 않거나, 같은 문제를 다시 틀릴 때. 어느 개념이 약한지 개념별로 보고 싶을 때는 아래 **개념 상태 나누기**를 쓴다.

## 진행

1. 틀린 문제와 사용자의 답·풀이를 받는다. 여러 개면 서너 개부터 본다.
2. 문제마다 틀린 이유를 사용자와 함께 가른다.

| 틀린 이유 | 뜻 | 다음에 할 것 |
| --- | --- | --- |
| 개념을 모름 | 필요한 내용을 몰랐다 | 그 부분을 다시 읽고 `04_내_말로_설명해_보기.md` |
| 헷갈림 | 비슷한 것과 섞였다 | `03_나란히_놓고_비교하기.md` |
| 적용을 못 함 | 아는데 문제에 쓰지 못했다 | 비슷한 문제를 `05_힌트를_받으며_풀기.md`로 |
| 문제를 잘못 읽음 | 조건이나 묻는 것을 놓쳤다 | 묻는 것에 밑줄 긋고 다시 풀기 |
| 실수 | 계산이나 옮겨 적기에서 틀렸다 | 검산 순서 정하기 |
| 시간 부족 | 알지만 시간이 모자랐다 | 시간을 재며 풀기 |

3. 이유별로 몇 개인지 세어 가장 많은 이유 하나를 고른다.
4. 그 이유에 맞는 다음 행동 하나를 정하고, 틀린 문제는 며칠 뒤 다시 풀 목록에 넣는다.

## 지켜 줄 것

- 틀린 이유는 사용자가 정한다. 에이전트는 풀이를 보고 의견을 낼 뿐이다.
- 탓하지 않는다. 틀린 문제는 공부할 곳을 알려 주는 자료다.
- 정답과 해설은 교재의 것을 기준으로 삼는다.

**결과:** 문제별 틀린 이유, 가장 많은 이유, 다시 풀 문제 목록.

## 개념 상태 나누기

틀린 문제 하나하나가 아니라, 이번 공부에서 낸 답을 모아 **개념별로 어떤 상태인지** 본다. 문제 단위의 "왜 틀렸나"와 달리 "이 개념은 지금 어디쯤인가"를 보는 방법이다.

### 진행

1. 이번 공부에서 사용자가 낸 답을 모은다. 답이 한두 개뿐이면 나누지 않고 "아직 판단하기 이르다"고 알린다.
2. 개념마다 상태를 의견으로 나누고 근거가 된 답과 자료의 위치를 붙인다. 사용자가 고친다.

| 상태 | 답에서 보이는 것 | 다음에 할 것 |
| --- | --- | --- |
| 이해함 | 자료를 보지 않고 맞게 설명하거나 적용했다 | 간격을 두고 가끔 확인(`08_간격을_두고_다시_보기.md`) |
| 부분적으로 이해함 | 맞는 부분과 빠진 부분이 섞여 있다 | 빠진 부분만 다시 읽고 `04_내_말로_설명해_보기.md` |
| 잘못 이해함 | 틀린 내용을 맞다고 설명했다 | 자료의 해당 위치와 나란히 놓고 `03_나란히_놓고_비교하기.md`, 고친 뒤 새 문제로 확인 |
| 계속 잊음 | 전에는 맞혔는데 날짜가 지나면 틀린다 | 복습 기록에서 간격을 당기고 `07_문제로_꺼내_보기.md` |
| 연습이 더 필요한 스킬 | 개념은 맞게 말하는데 풀이나 적용에서 막힌다 | `05_힌트를_받으며_풀기.md`, `09_섞어서_풀기.md` |

3. **약한 순서를 정한다.** 잘못 이해한 개념을 먼저 본다. 맞다고 믿고 있어 시험에서도 자신 있게 틀리기 쉽기 때문이다. 그다음은 사용자가 아는 시험 비중이나 자신의 판단으로 고른다. 비중을 모르면 추측하지 않는다.
4. **짧은 복습 계획을 짠다.** 전부 다시 하지 않고 우선순위 위쪽 두세 개만, 위 표의 다음 행동 하나씩으로 짠다.

### 지켜 줄 것

- 상태 나누기는 에이전트의 의견이다. 사용자가 이번에 낸 답만 근거로 삼고, 사용자의 성향이나 능력을 짐작해 붙이지 않는다.
- **계속 잊음**은 여러 날의 복습 기록이 있어야 말할 수 있다. 기록이 없으면 이 칸은 비워 둔다.
- 자료에 근거한 판단인지, 일반 지식으로 짚은 것인지 구분해 말하고 뒤의 경우는 교재에서 확인하게 한다.

**결과:** 개념별 상태 목록, 약한 순서, 두세 개만 짧게 다시 볼 계획.
