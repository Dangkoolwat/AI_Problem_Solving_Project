# 모의고사 풀기

> 이 파일은 `.skills/learning-toolkit/SKILL.md`의 방법별 안내다. 공통 원칙은 SKILL.md를 먼저 읽는다.

**언제:** 단원별로 공부한 내용을 시험처럼 한 번에 풀어 보고 싶을 때. 시험 형식에 익숙해지고, 어느 주제에서 점수를 잃는지 보고 싶을 때. 두 단원 이상을 공부한 뒤에 쓴다.

실제 시험 문제를 맞히는 방법이 아니라, 공부한 범위로 연습하고 빈틈을 찾는 방법이다. 시험 중에는 도움을 주지 않는다.

## 진행

1. **조건을 받는다.** 범위, 시험 형식(문항 수, 객관식·서술형 비율), 배점, 시간을 묻는다. 사용자가 아는 만큼만 받고 모르는 것은 `[확인 필요]`로 둔다. 형식을 모르면 에이전트가 임시로 정한 형식이라고 밝힌다. 사용자가 기출 문제나 시험지를 주면 그 형식에 맞춘다.
2. **구성을 제안한다.** 쉬운 문제, 중간 문제, 어려운 문제, 개념 문제, 적용 문제를 섞는 비율을 보여 주고 사용자가 고친다. 문제마다 근거가 되는 자료의 위치를 정해 둔다.
3. **문제를 낸다.** 정답과 근거는 보여 주지 않는다. 문제 묶음을 한꺼번에 낼지 한 문제씩 낼지는 사용자가 고른다. 파일로 저장한다면 문제와 정답·채점을 나눠 저장한다.
4. **사용자가 답한다.** 자료를 보지 않고 푼다. 시간을 재고 싶으면 사용자가 직접 재서 알려 준다.
5. **채점한다.** 문제마다 맞음, 부분 맞음, 틀림을 알리고 근거 위치와 해설을 붙인다. 서술형 채점은 정답 판정이 아니라 의견이다(`07_문제로_꺼내_보기.md`).
6. **감점 주제표를 만든다.** 틀린 문제를 단원이나 개념별로 묶어 어디서 점수를 잃었는지 보여 준다. 배점은 사용자가 준 것을 쓰고, 합계는 검산한다.
7. **다음 행동을 잇는다.** 가장 많이 잃은 주제 하나를 사용자가 고르게 한다. 틀린 이유는 `06_틀린_문제_돌아보기.md`, 약한 개념은 같은 파일의 개념 상태 나누기, 다시 볼 날짜는 `08_간격을_두고_다시_보기.md`로 잇는다.

## 한 문제씩 이어 가는 시뮬레이션 (선택)

사용자가 원하면 한 문제씩 내고 답에 따라 다음 문제의 수준을 조정한다(`07_문제로_꺼내_보기.md`의 문제 유형과 난이도). 진행하면서 다음을 기록한다.

- 맞힌 문제와 틀린 문제의 수
- 약해 보이는 개념
- 반복해서 나타난 틀린 방식
- 사용자가 알려 준 풀이 시간(에이전트는 시간을 측정하지 못한다)

끝나면 가장 잘한 부분, 가장 약한 부분, 먼저 다시 볼 개념, 남은 기간의 짧은 집중 계획을 알려 준다. 기록은 이번 답에서 관찰한 것만 적는다. 사용자의 성향이나 사고방식을 짐작해 적지 않는다.

## 지켜 줄 것

- 자료와 사용자가 준 문제에서만 문제를 낸다. 새로 만든 문제는 만든 것이라고 밝히고 답의 근거를 붙인다. 근거를 찾지 못한 문제는 내지 않거나 `[확인 필요]`로 둔다.
- 실제 시험에 나올 문제라고 말하지 않는다. 출제 경향이나 합격 가능성을 예측하지 않는다. 점수는 이번 연습의 결과일 뿐이다.
- 기출 문제는 사용자가 준 것만 쓴다. 에이전트가 만든 문제를 기출이라고 부르지 않는다.
- 법령, 제도, 수치는 자료의 기준 시점을 밝히고 최신 내용을 사용자가 확인하게 한다.
- 에이전트의 채점과 계산도 틀릴 수 있다. 교재의 정답과 해설이 있으면 그것을 기준으로 삼는다.
- 처음 배우는 단원에는 쓰지 않는다. 먼저 단원별로 익힌 뒤에 푼다. 처음에는 평소보다 많이 틀릴 수 있다고 미리 알린다.
- 불안이 크거나 잠을 못 자는 상태로 보이면 문제를 더 내지 않고 먼저 듣는다.
- 만든 모의고사를 다른 사람에게 나눠 주거나 올리는 일은 저작권과 관련될 수 있으니 사용자가 확인하도록 알린다.

**결과:** 문제 묶음, 사용자의 답, 근거가 붙은 채점, 감점 주제표, 다시 볼 주제 목록.

**이어서:** 약한 단원을 다시 보려면 `10_시험_범위로_점검하기.md`, 틀린 이유를 가르려면 `06_틀린_문제_돌아보기.md`로 잇는다.
