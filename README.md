# 나의 문제 해결 작업공간 (AI_Problem_Solving_Project)

AI를 써 보고 싶긴 한데, 막상 채팅창을 열면 무엇부터 물어야 할지 막막했던 적 있으신가요? 취업·이직·회사 일·공부·일상 고민은 서로 이어져 있는데, 매번 프롬프트를 새로 찾고 처음부터 다시 설명하다 지치곤 합니다.

이곳은 그런 막연한 고민을 AI 에이전트와 이야기하며 조금씩 풀어 보는 작업공간입니다. 처음부터 거창한 결과를 만들 필요는 없습니다. 지금 불편한 점을 말하고, 그중 하나를 골라 작은 해결을 시도해 보세요.

> 이 프로젝트는 무료로 배포하는 오픈 소스([CC BY 4.0](LICENSE))입니다. 누구나 가져다 쓰고 고쳐 쓸 수 있습니다.

## 어떻게 문제를 푸나요

사람이 모든 것을 혼자 정리하거나, 반대로 AI에게 통째로 맡기지 않습니다. **사람이 할 일(선택·확인)과 에이전트가 할 일(정리·제안)**을 나누어 함께 풀어 갑니다.

**설계 원칙**

- **큰 문제를 작게 나눕니다.** 큰 목표를 한꺼번에 풀려 하지 않고 작은 문제 몇 개로 쪼갭니다.
- **중요한 몇 가지만 골라 진행합니다.** 나눈 문제를 전부 다 하지 않고 중요한 것 몇 개만 골라 해 봅니다. 고르는 사람은 사용자이고 에이전트는 의견을 보탭니다.
- **작업 순서를 도구 상자에 담았습니다.** 일상, 회사 일, 공부에 자주 쓰는 해결 순서를 '도구 상자(스킬)'로 묶어 두었습니다. 필요한 것을 하나씩 꺼내 써 볼 수 있습니다.

**함께 지키는 원칙**

- **경험이 먼저입니다.** 완성본을 자동으로 뽑아 주는 자판기가 아니라, 직접 해 보며 감을 익히는 작업공간입니다.
- **에이전트가 먼저 묻고 의견을 냅니다.** 무엇을 원하는지 먼저 듣고 방법을 2~3가지로 추려 각각 얻는 결과와 아쉬운 점을 알려 줍니다. 맞아 보이는 방법은 이유와 함께 먼저 권하지만, 마지막에 고르는 사람은 언제나 사용자입니다.
- **방법 이름을 외울 필요가 없습니다.** 정해진 순서도 없습니다. 고민에 맞는 방법을 에이전트가 제안합니다.
- **확인은 사람의 몫입니다.** 에이전트가 모르는 것은 지어내지 않고 `[확인 필요]`로 남깁니다. 숫자·날짜·출처는 직접 확인해야 합니다.
- **기록을 남깁니다.** 고른 방법, 확인한 내용, 다시 쓸 요청문을 파일로 남겨 다음에 이어서 할 수 있습니다.

## 이런 분께 잘 맞아요

- 취업·이직을 준비하거나 직장 업무·공부를 AI와 차근차근 정리해 보고 싶은 20~30대 비개발자
- 프롬프트를 외우기보다, 이 프로젝트의 구조를 익혀 **나만의 워크플로우**로 고쳐 써 보고 싶은 분
- AI에게 맡기고 끝내기보다, 선택지를 비교하고 직접 확인하며 결과물을 만들어 가고 싶은 분

## 지금 바로 시작해 보세요

1. **처음이라면** → [설치 가이드](docs/00_설치_가이드.md)에서 프로젝트를 내려받고 에이전트를 연결하세요.
2. **설치를 마쳤다면** → [시작하기](docs/00_시작하기.md)에서 사용법을 훑고, 막막할 땐 [사례집](docs/01_사례집.md)의 첫 요청문을 그대로 써 보세요.
3. **이미 쓰고 있다면** → [업데이트 가이드](docs/00_업데이트_가이드.md)로 내 작업 폴더 4개는 지키면서 최신 버전으로 업데이트할 수 있습니다.

이 폴더를 AI 에이전트의 작업 폴더로 열고 아래 말을 건네 보세요.

```text
이 프로젝트의 AGENTS.md를 읽고 내 고민을 함께 해결해 줘.
내 이야기를 먼저 듣고 필요한 것부터 한두 가지씩 물어봐 줘.
방법을 2~3가지 보여 주고 네 의견도 이유와 함께 말해 줘. 고르는 건 내가 할게.
```

그다음에는 고민을 있는 그대로 이야기하면 됩니다.

> “할 일이 많은데 무엇부터 시작해야 할지 모르겠어요.”
>
> “관심 있는 채용공고를 비교하는 기준을 잡기 어려워요.”
>
> “시장 뉴스가 너무 많아서 무엇을 먼저 봐야 할지 모르겠어요.”

예시를 그대로 따라 하지 않아도 됩니다. 내 고민으로 편하게 시작하세요. 어떤 자료가 필요한지 모르겠다면 그걸 먼저 물어봐도 됩니다.

## 이렇게 진행합니다

1. **고민을 이야기합니다.** 무엇이 궁금하거나 불편한지 편하게 말해 주세요. 자료가 없어도 시작할 수 있습니다.
2. **작은 목표를 정합니다.** 에이전트가 질문하고 선택지를 제안하면, 오늘 다룰 문제를 직접 고릅니다.
3. **필요할 때 자료를 마련하고 저장합니다.** 대화만으로 짧게 끝나는 일은 바로 진행하고, 파일·링크 자료나 나중에 이어갈 일은 원본을 `source/`에, 분석할 자료를 `data/`에 저장해 읽을 수 있는지 확인한 뒤 분석합니다.
4. **복잡한 고민은 업무 지도로 정리합니다(선택).** 필요한 자료, 에이전트에게 맡길 일, 원하는 결과, 직접 확인할 점을 대화하며 표로 채울 수 있습니다. 가벼운 고민은 이 단계를 건너뛰어도 됩니다.
5. **한번 시도합니다.** 고민에 맞게 비교표, 계획, 글, 보고서 등 필요한 첫 결과를 만듭니다.
6. **확인하고 개선합니다.** 에이전트가 제안한 개선점과 이유를 살펴보고, 바꾸고 싶은 것을 선택합니다. 중요한 정보는 직접 확인합니다.
7. **다음에 쓸 수 있게 남깁니다.** 선택한 방법과 확인한 내용, 다시 사용할 요청문을 작업별 폴더에 저장합니다.

## 나에게 맞는 워크플로우 만들기

워크플로우는 목표를 이루기 위한 작업 순서입니다. 고민을 이야기하면 에이전트가 필요한 자료와 방법을 제안하고 **사람과 에이전트가 각각 맡을 일**을 계획으로 보여 줍니다. 계획을 보고 마음에 들지 않으면 바꾸고, 괜찮으면 그대로 진행합니다.

- **한 단계씩 함께하기:** 한 단계가 끝날 때마다 결과를 보고 다음 행동을 고릅니다.
- **계획 승인 후 이어서 하기:** 준비된 자료로 할 수 있는 단계까지 이어서 진행한 뒤 결과를 확인합니다.

중요하거나 복잡한 일이라면 어떤 AI 모델이 맞을지 물어봐도 됩니다. 지금 쓸 수 있는 모델과 도구, 비용·속도를 확인한 범위에서 이유를 알려 달라고 해 보세요. 실제로 쓸 수 있는 모델은 계정과 환경마다 다르며 무엇을 쓸지는 사용자가 고릅니다.

예를 들어 관심 공고 찾기 → 내 경험과 비교 → 자소서 초안과 다듬기 → 예상 질문 만들기를 나만의 순서로 정할 수 있습니다. 필요한 공고와 경험 자료, 직접 고를 부분만 계획에서 확인해 주세요. 원하는 방식을 이미 말했다면 다시 고르지 않아도 됩니다.

마음에 드는 순서는 `outputs/` 폴더에 Markdown 파일로 저장해 달라고 해 보세요. 나중에 새 자료로 다시 부탁하면 에이전트가 저장된 순서와 지금 쓸 수 있는 도구를 살펴 계획을 먼저 보여 주고 확인받은 뒤 이어 갑니다. 이전 자료와 결과는 그대로 남깁니다.

```text
내 고민을 듣고 필요한 자료와 작업 단계를 함께 정해 줘.
각 단계에서 에이전트가 할 일과 내가 선택·확인할 일을 나눠 계획으로 보여 줘.
내가 계획을 확인하면 [한 단계씩 / 가능한 단계 이어서] 진행하고, 다음에 다시 쓸 수 있게 워크플로우를 저장해 줘.
```

에이전트 하나가 상황에 맞는 도구 상자를 꺼내 참고하는 방식입니다. 파일 읽기·저장이나 인터넷 검색이 되는지는 쓰는 AI 도구와 설정에 따라 다릅니다. 여러 도구 상자를 엮어 쓴다고 해서 에이전트가 혼자 감시하거나 여러 일을 동시에 돌리지는 않습니다.

## 폴더 사용법

**안내와 지침**

- `docs/`: 사람이 읽는 안내입니다. [설치 가이드](docs/00_설치_가이드.md), [업데이트 가이드](docs/00_업데이트_가이드.md), [시작하기](docs/00_시작하기.md), [사례집](docs/01_사례집.md)과 사례, 참고 문서가 있습니다.
- `AGENTS.md`: 에이전트가 대화하고 작업할 때 참고하는 지침입니다.
- `instructions/`: 길거나 가끔 쓰는 상세 규칙입니다. 선택지 제시 방식, 워크플로우 구성과 재사용(`워크플로우_구성과_재사용.md`), 방법 메뉴(`방법_메뉴.md`: 고민에 맞는 방법을 고르고 여러 도구 상자를 엮을 때 보는 목록), 스킬 추가 점검(`스킬_추가_점검.md`: 새 스킬을 넣거나 바꿀 때 마지막에 확인하는 목록) 등이 있습니다.
- `instructor/`: 수업 진행 가이드, 배포 점검표, 에이전트 동작 시험 키트([`test_kit/`](instructor/test_kit/README.md))가 들어 있습니다. 평소에는 에이전트가 읽지 않지만, 나만의 지침이나 스킬을 만든 뒤 잘 작동하는지 어떻게 시험해 보는지 참고할 수 있게 함께 열어 둔 예시입니다.

**양식 (`templates/`)**

- `01_문제해결_업무지도.md`: 고민과 작은 목표를 정하고 준비할 자료·할 일·결과·확인할 점·다시 쓸 방법을 정리하는 양식입니다.
- `02_확인과_개선.md`: 개선 제안, 직접 확인한 내용, 고른 수정 사항을 적는 양식입니다.
- `03_취업_고민_정리.md`: 취업 고민과 공고·경험을 필요할 때 정리하는 양식입니다.
- `04_업무_소통과_진행_기록.md`: 이메일·회의·연결된 업무 도구의 내용을 쌓고 바뀐 점을 남기는 양식입니다.
- `05_자료_수집_기록.md`: 웹페이지·문서·영상 등에서 찾은 내용과 출처를 적는 양식입니다.
- `06_기획_초안.md`: 필요한 항목만 골라 문제·아이디어·실행과 확인 방법을 정리하는 양식입니다.

**도구 상자 (`.skills/`)**

- `job-search-toolkit`: 취업 고민에 맞는 공고 비교·경험 정리 방법을 제안합니다.
- `workplace-toolkit`: 회의 준비·정리, 보고서, 답장, 업무 현황, 피드백·거절·회고를 돕습니다.
- `learning-toolkit`: 전공 원서, 자격증, 새 업무를 공부하는 성인을 위한 도구 상자입니다. 이해, 암기, 문제 풀이, 복습, 시험 연습(모의고사, 약한 개념 찾기)에 맞는 방법을 고릅니다.
- `thinking-toolkit`: 문제 진단, 큰 문제를 나눠 핵심 고르기, 아이디어 넓히기, 선택 비교, 지금 할 일 고르기 등 생각을 정리합니다.
- `goal-achievement-toolkit`: 목표와 작은 실천을 정하고 돌아볼 방법을 고릅니다. [취업 4](docs/cases/취업_4_직무_방향_잡기.md)와 [생활 5](docs/cases/생활_5_계획을_자꾸_못_지킬_때.md) 사례를 참고하세요.
- `planning-toolkit`: 행사·서비스·업무 개선 등 다양한 기획을 대화하고 검토합니다.
- `research-toolkit`: 기업·산업·관심 주제를 출처와 함께 조사합니다.
- `data-toolkit`: CSV·엑셀 같은 표 자료를 살펴보고 정리·분석합니다.
- `evidence-check`: 여러 문서와 표의 주장·숫자를 서로 대조합니다.
- `update-workflow`: 새 자료가 생겼을 때 이전 결과를 보존하며 갱신합니다.
- `clear-summary`: 긴 결과의 핵심을 먼저, 쉽게 전합니다.
- `persuasion-writing`: 모집글·소개글·안내문·제안서처럼 읽는 사람의 행동을 이끄는 설득 글을 구성하거나 약점을 점검합니다.
- `infographic-toolkit`: 내용을 한 장의 그림으로 만듭니다.
- `humanize-korean`: 글의 사실과 원래 말투를 지키면서 어색한 표현을 다듬는 참고 지침입니다. 글을 다듬고 싶을 때 에이전트에게 이 스킬을 읽고 적용해 달라고 요청할 수 있습니다.

**내 작업 (`source/`, `data/`, `outputs/`, `agents_logs/`)**

- `source/`: 찾았거나 받은 원본 파일을 그대로 두는 곳입니다.
- `data/`: 작업에 쓸 자료를 넣는 곳입니다. 개인정보와 회사 기밀은 빼거나 가린 뒤 넣어 주세요.
- `outputs/`: 업무 지도, 확인 기록, 결과물을 저장하는 곳입니다.
- `agents_logs/`: 에이전트가 파일을 만들거나 고친 기록을 남기는 곳입니다. `INDEX.md`는 작업 목록이며 새 대화에서 에이전트가 이어갈 작업을 찾을 때 가장 먼저 읽습니다. 이 기록은 내 컴퓨터에만 남고 Git으로 공유되지 않습니다.

`templates/`의 빈 양식과 `source/`의 원본, `data/`의 정리 자료는 그대로 두고 `outputs/`에 작업별 폴더를 만들어 저장해 달라고 요청하세요. 고친 결과는 이전 파일과 이름을 구분해 저장하면 나중에 어떻게 달라졌는지 비교하기 편합니다.

글로 정리한 기록(Markdown)은 지우지 않고 남깁니다. `source/`에 둔 PDF·PPT·엑셀 같은 원본은 필요 없을 때 지울 파일 이름을 콕 집어 삭제해 달라고 할 수 있습니다. 원본을 지우면 나중에 원래 내용과 다시 맞춰 보기 어려우니 관련 기록은 남기고 지웠다는 표시를 해 둡니다.

## 이 프로젝트를 만든 이유와 앞으로의 계획

### 만든 이유와 강의에서의 목적

AI 업무 자동화 강의에서 에이전트를 다루며 만든 실습 프로젝트입니다. 20~30대가 가장 많이 고민하는 주제는 취업·이직 준비와 회사 일을 덜 힘들이고 해내는 방법입니다. 이 고민들을 여러 프로젝트로 쪼개지 않고 **하나의 작업공간에 모았습니다**. 고민은 서로 이어져 있어서 한곳에서 오가며 풀어 볼 수 있어야 하기 때문입니다.

거창한 에이전트 설계 이론을 가르치려는 것이 아닙니다. 이 프로젝트가 **어떤 생각과 구조로 짜여 있는지 익힌 뒤**, 나중에 **나만의 작업 순서로 고쳐 쓰며** AI와 일하는 감을 직접 익히고 그 경험을 내 글로 남기는 것이 목표입니다.

### 어떻게 만들어 왔나

1. **뼈대를 세웠습니다.** 고민을 이야기하고 작은 목표를 고른 뒤 자료를 모아 시도하고 확인·개선하는 일곱 단계 흐름과 에이전트 지침(`AGENTS.md`)을 정했습니다.
2. **방법을 도구 상자로 나누었습니다.** 취업, 직장, 공부, 기획, 조사, 자료 분석 등 고민 종류별 도구 상자를 만들고 널리 알려진 공개 스킬은 출처와 라이선스를 지키며 참고했습니다. 목록은 [`.skills/SOURCES.md`](.skills/SOURCES.md)에 있습니다.
3. **예시 중심으로 안내를 다듬었습니다.** 읽기 쉽도록 `docs/`를 시작하기, 사례집, 참고 문서로 다시 짰습니다. 여러 고민 사례로 같은 문제도 방법에 따라 다른 결과가 나오는 모습을 보여 줍니다.
4. **설계 리뷰와 동작 시험 키트를 갖추었습니다.** 여러 에이전트로 교차 검토하며 지침의 모호함을 줄이고 불필요한 토큰을 덜어냈습니다. 선택지를 번호로 고르는 규칙과 5종 [시험 키트](instructor/test_kit/README.md)도 이때 마련했습니다.
5. **실전 사고법과 소통 공식을 녹여 넣었습니다.** 직접 만들어 써 온 프롬프트 모음과 공부·기획·설득·업무 소통 방법을 이 작업공간에 맞게 다시 다듬어 도구 상자에 담았습니다.
6. **공유할 기반을 마련했습니다.** 누구나 활용하고 고쳐 쓸 수 있도록 CC BY 4.0 라이선스와 출처 안내를 정리했습니다.

### 앞으로 할 일

- **한국 청년의 현실에 맞는 워크플로우를 더 넓힙니다.** 20~30대가 자주 겪는 상황에 맞춰 사례와 방법을 꾸준히 보태려고 합니다.
- 사례의 첫 요청문을 실제 에이전트로 돌려 보고 기대한 대로 움직이는지 확인합니다.
- [시험 키트](instructor/test_kit/README.md)로 기준 점수를 재며 지침과 스킬을 계속 다듬습니다.
- 실습에서 나온 막힌 지점과 의견을 사례와 스킬에 반영합니다.
- Claude, ChatGPT, Gemini, Codex 등 서로 다른 에이전트와 환경에서 지침과 스킬이 잘 작동하는지 확인합니다.

위 내용은 앞으로의 계획입니다. 실제 수업에서 써 보며 얼마나 편한지는 앞으로 더 확인해 가야 합니다. 의견이나 제안은 아래 이메일이나 GitHub 이슈로 남겨 주세요.
