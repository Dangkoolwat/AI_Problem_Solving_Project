# 나의 문제 해결 작업공간

막연한 고민을 AI 에이전트와 이야기하며 풀어 보는 작업공간입니다. 취업, 업무, 공부, 일상처럼 주제는 무엇이든 괜찮습니다. 처음부터 거창한 결과를 만들 필요는 없습니다. 지금 불편한 점을 말하고, 그중 하나를 골라 작은 해결을 시도해 보세요.

## 이렇게 진행합니다

1. **고민을 이야기합니다.** 무엇이 궁금하거나 불편한지 편하게 말해 주세요. 자료가 없어도 시작할 수 있습니다.
2. **작은 목표를 정합니다.** 에이전트가 질문하고 선택지를 제안하면, 오늘 다룰 문제를 직접 고릅니다.
3. **자료를 마련하고 저장합니다.** 확보한 원본은 `source/`에 보관하고, 분석할 자료와 대화로 정리한 내용은 `data/`에 저장합니다. 에이전트가 읽을 수 있는지 확인한 뒤 분석합니다.
4. **업무 지도를 채웁니다.** 필요한 자료, 에이전트에게 맡길 일, 원하는 결과, 직접 확인할 점을 대화하면서 적습니다. 처음부터 모든 칸을 채우지 않아도 됩니다.
5. **한번 시도합니다.** 고민에 맞게 비교표, 계획, 글, 보고서 등 필요한 첫 결과를 만듭니다.
6. **확인하고 개선합니다.** 에이전트가 제안한 개선점과 이유를 살펴보고, 바꾸고 싶은 것을 선택합니다. 중요한 정보는 직접 확인합니다.
7. **다음에 쓸 수 있게 남깁니다.** 선택한 방법과 확인한 내용, 다시 사용할 요청문을 작업별 폴더에 저장합니다.

## 나에게 맞는 워크플로우 만들기

워크플로우는 목표를 이루기 위한 작업 순서입니다. 고민을 이야기하면 에이전트가 필요한 자료와 방법을 제안하고, 필요한 스킬과 도구를 조합해 **사람과 에이전트가 각각 할 일**을 계획으로 보여 줍니다. 계획을 살펴보고 바꾸거나 승인할 수 있습니다.

- **한 단계씩 함께하기:** 단계별 결과를 보고 다음 행동을 고릅니다.
- **계획 승인 후 이어서 하기:** 준비된 자료를 바탕으로 가능한 단계를 이어서 수행하고 결과를 확인합니다.

중요하거나 복잡한 작업에서는 에이전트에게 어떤 모델이 적합할지도 물어볼 수 있습니다. 사용 가능한 모델과 필요한 도구, 비용이나 속도를 확인한 범위에서 이유를 설명하도록 요청하세요. 모델의 실제 이용 가능 여부는 계정과 환경에 따라 다르며, 최종 선택은 수강생이 합니다.

예를 들어 관심 공고 찾기 → 내 경험과 비교 → 자소서 초안과 다듬기 → 예상 질문 만들기를 나만의 흐름으로 정할 수 있습니다. 필요한 공고와 경험 자료, 직접 선택할 부분을 계획에서 확인해 주세요. 어느 방식을 원하는지 이미 말했다면 다시 고를 필요는 없습니다.

마음에 드는 흐름은 에이전트에게 `outputs/`에 Markdown으로 저장해 달라고 요청하세요. 나중에 새 자료로 다시 요청하면 에이전트가 저장된 흐름과 현재 사용 가능한 도구를 확인하고, 적용할 계획을 보여 준 뒤 승인받아 이어 갑니다. 이전 자료와 결과는 보존합니다.

> “내 고민을 듣고 필요한 자료와 작업 단계를 함께 정해 줘. 각 단계에서 에이전트가 할 일과 내가 선택·확인할 일을 나눠 계획으로 보여 줘. 내가 계획을 확인하면 [한 단계씩 / 가능한 단계 이어서] 진행하고, 다음에 다시 쓸 수 있게 워크플로우를 저장해 줘.”

하나의 에이전트가 필요한 스킬을 참고하는 방식입니다. 스킬을 실제로 읽을 수 있는지와 검색·파일 저장은 사용하는 환경에 따라 다릅니다. 여러 스킬을 조합한다고 자동 감시나 병렬 실행이 시작되지는 않습니다.

## 처음 시작할 때

처음이라면 [시작하기](docs/00_시작하기.md)부터 보세요. 폴더를 여는 방법, 첫 말, 결과를 확인하고 고치는 법이 한 장에 있습니다. 어떤 고민으로 시작할지 모르겠다면 [사례집](docs/01_사례집.md)에서 가까운 것을 골라 첫 요청문을 그대로 써 보세요. 취업·직장·공부·생활·만들기 사례 31개와, 같은 고민을 다른 방법으로 풀어 보는 비교 사례 3개가 있습니다.

이 폴더를 AI 에이전트의 작업 폴더로 열고 아래 말을 건네 보세요.

> 이 프로젝트의 `AGENTS.md`를 읽고 제 고민을 함께 해결해 주세요. 먼저 제 이야기를 듣고 질문해 주세요. 기존 업무 지도 양식을 대화하면서 조금씩 채우고 싶어요. 쉬운 말로 설명하고, 제가 고를 수 있도록 해결 방법과 개선점도 제안해 주세요.

그다음에는 고민을 있는 그대로 이야기하면 됩니다.

> “할 일이 많은데 무엇부터 시작해야 할지 모르겠어요.”
>
> “관심 있는 채용공고를 비교하는 기준을 잡기 어려워요.”
>
> “시장 뉴스가 너무 많아서 무엇을 먼저 봐야 할지 모르겠어요.”

어느 예시를 따라야 하는 것은 아닙니다. 내게 필요한 문제로 시작해 주세요. 자료를 찾거나 정리하는 일이 필요하면 에이전트에게 어떤 자료가 필요한지부터 물어볼 수 있습니다.

## 폴더 사용법

- `AGENTS.md`: 에이전트가 대화하고 작업할 때 참고하는 지침입니다.
- `instructions/워크플로우_구성과_재사용.md`: 에이전트가 워크플로우를 계획·실행·저장하고 다시 활용할 때 참고하는 안내입니다.
- `templates/01_문제해결_업무지도.md`: 고민과 작은 목표를 정하고 입력·처리·결과·확인·재사용을 정리하는 양식입니다.
- `templates/02_확인과_개선.md`: 개선 제안, 직접 확인한 내용, 선택한 수정을 기록하는 양식입니다.
- `.skills/job-search-toolkit/`: 취업 고민에 맞는 공고 비교·경험 정리 방법을 제안하는 도구 상자입니다.
- `templates/03_취업_고민_정리.md`: 취업 고민과 공고·경험을 필요할 때 정리하는 양식입니다.
- `templates/04_업무_소통과_진행_기록.md`: 이메일·회의·연결된 업무 도구의 내용을 쌓고 변경 사항을 남기는 양식입니다.
- `templates/05_자료_수집_기록.md`: 웹페이지·문서·영상 등에서 확보한 내용과 출처를 기록하는 양식입니다.
- `templates/06_기획_초안.md`: 필요한 항목만 골라 문제·아이디어·실행과 확인 방법을 정리하는 양식입니다.
- `.skills/planning-toolkit/`: 행사·서비스·업무 개선 등 다양한 기획을 대화하고 검토하는 도구 상자입니다.
- `.skills/goal-achievement-toolkit/`: 목표와 작은 실천을 정하고 돌아볼 방법을 고르는 도구 상자입니다. [취업 4](docs/cases/취업_4_직무_방향_잡기.md)와 [생활 5](docs/cases/생활_5_계획을_자꾸_못_지킬_때.md) 사례를 참고하세요.
- `.skills/humanize-korean/`: 글의 사실과 원래 말투를 지키면서 어색한 표현을 다듬는 참고 지침입니다. 글을 다듬고 싶을 때 에이전트에게 이 스킬을 읽고 적용해 달라고 요청할 수 있습니다.
- `.skills/thinking-toolkit/`: 문제 진단, 큰 문제를 나눠 핵심 고르기, 아이디어 넓히기, 선택 비교, 지금 할 일 고르기 등 생각을 정리하는 도구 상자입니다.
- `.skills/learning-toolkit/`: 전공 원서, 자격증, 새 업무를 공부하는 성인을 위한 도구 상자입니다. 이해, 암기, 문제 풀이, 복습에 맞는 방법을 고릅니다.
- `.skills/workplace-toolkit/`: 회의 준비·정리, 보고서, 답장, 업무 현황을 돕는 도구 상자입니다.
- `.skills/research-toolkit/`: 기업·산업·관심 주제를 출처와 함께 조사하는 도구 상자입니다.
- `.skills/data-toolkit/`: CSV·엑셀 같은 표 자료를 살펴보고 정리·분석하는 도구 상자입니다.
- `.skills/evidence-check/`: 여러 문서와 표의 주장·숫자를 서로 대조하는 도구 상자입니다.
- `.skills/update-workflow/`: 새 자료가 생겼을 때 이전 결과를 보존하며 갱신하는 도구 상자입니다.
- `.skills/clear-summary/`: 긴 결과의 핵심을 먼저, 쉽게 전하는 도구 상자입니다.
- `.skills/infographic-toolkit/`: 내용을 한 장의 그림으로 만드는 도구 상자입니다.
- `instructions/방법_메뉴.md`: 에이전트가 고민에 맞는 방법을 고르고 여러 도구 상자를 엮을 때 보는 목록입니다.
- `docs/`: 사람이 읽는 안내입니다. [시작하기](docs/00_시작하기.md), [사례집](docs/01_사례집.md)과 사례 34개, 참고 문서가 있습니다.
- `source/`: 수집하거나 제공받은 원본을 보관하는 곳입니다.
- `data/`: 작업에 필요한 자료를 넣는 곳입니다. 개인정보와 기밀을 빼거나 가린 뒤 사용해 주세요.
- `outputs/`: 수강생의 업무 지도, 확인 기록, 결과물을 저장하는 곳입니다.
- `agents_logs/`: 에이전트가 파일을 만들거나 고친 모든 작업(수강생 실습 포함)의 기록과 관련 산출물을 보관하는 곳입니다. `INDEX.md`는 작업 목록이며, 새 대화에서 에이전트가 이어갈 작업을 찾을 때 가장 먼저 읽습니다.

`templates/`의 빈 양식과 `data/`의 원본은 그대로 두고, 에이전트에게 `outputs/`에 작업별 폴더를 만들어 기록해 달라고 요청하세요. 고친 결과는 이전 결과와 구분해 저장하면 나중에 변화를 살펴보기 편합니다.

Markdown 기록은 유지하는 것이 원칙입니다. `source/`의 PDF·PPT·엑셀 등 원본은 필요하지 않을 때 삭제할 파일을 지정해 요청할 수 있습니다. 원본을 삭제하면 나중에 원문과 다시 대조하기 어려울 수 있으므로 관련 기록은 보존하고 삭제 상태를 남깁니다.

## 확인할 때 기억해 주세요

에이전트가 적은 출처가 실제로 주장과 맞는지는 직접 살펴봐야 합니다. 숫자는 날짜와 단위도 함께 확인하세요. 확인하지 못한 내용은 `[확인 필요]`로 남기고, 직접 확인한 일과 앞으로 할 일을 구분합니다.

인터넷 검색과 자료 접근 가능 여부는 사용하는 에이전트와 설정에 따라 다릅니다. 자료를 찾지 못했다면 에이전트에게 가능한 방법을 묻거나 직접 준비한 자료로 진행할 수 있습니다. 글 다듬기 스킬은 자연스러운 표현을 돕지만, 사실 확인이나 최종 판단을 대신하지 않습니다.
